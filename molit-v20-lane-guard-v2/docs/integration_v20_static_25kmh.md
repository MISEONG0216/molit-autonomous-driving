# V20: 25 km/h requested speed for locked LiDAR static avoidance

Based on `integration-v19-static-zone-gated`. No modifications to
traffic-light detection, traffic mission management, merge logic, V7
global-path profile, static waypoint zones, obstacle detection, or
local-path geometry.

## Shared avoidance speed

`config/integration_missions.json`:

```json
"static": {
  "avoidance_speed_kmh": 25.0,
  "avoidance_zones_wp": [[590, 760]]
}
```

The same value is parsed/validated in both main and the independent
LiDAR worker. It is applied to:
1. Main controller `target_speed_kmh` while `STATIC=AVOIDING`;
2. The initial local route generated by `StaticObstaclePlanner`;
3. The previously accepted route held by `AvoidancePathLatch`.

Without changing all three, the 5/10-km/h main cap or 8-km/h planner /
latch request would continue limiting the local manoeuvre.

The final vehicle target while avoiding is the minimum of
the active V7/traffic/merge mission target, 25 km/h static cap,
and the LiDAR route's 25-km/h recommendation. The actual
`COMP SPEED` depends on control dynamics; it may be lower or temporarily
higher during deceleration. The controller **does not instantly slow the
vehicle to 25 km/h at avoidance activation**.

While `CLEAR` or `ZONE_OFF`, the original V7 speed profile is still
in effect, up to `--max-speed 57`. During `STOP_REQUIRED` or stale
LiDAR data **inside** the static mission (or along a latched path),
the original full brake and fail-stop remain in effect.

## Safety limitations

- No new advance braking is added. The source planner triggers local
  avoidance at approximately 15m. Approaching that point at 57 km/h
  and commanding 25 km/h may still lead to path tracking errors or
  collisions before the speed can decrease.
- The 2.5m local Pure Pursuit lookahead from the earlier low-speed
  integration is **unchanged and has not been validated at 25 km/h**.
- The 7m assumed drivable corridor and fixed local path geometry are
  unchanged. Check MORAI road/lane boundaries before competition.
- A teammate's separate 25-km/h test does not by itself validate the
  V20 integrated controller or this specific local-path tracker.

## Ubuntu commands

```bash
cd ~/molit-autonomous-driving
git fetch origin
git switch integration-v20-static-avoid-25kph
git pull --ff-only origin integration-v20-static-avoid-25kph
source .venv/bin/activate

python3 -m unittest discover -s tests -p 'test_static_speed_25_v20.py' -v
python3 -m unittest discover -s tests -p 'test_static_zone_v19.py' -v
python3 -m unittest discover -s tests -p 'test_static_path_lock_v18.py' -v
python3 -m unittest discover -s tests -p 'test_static_integration_v17.py' -v
```

Start the traffic-light detector, LiDAR worker and main controller in
three distinct terminals. Verify worker startup line:

```text
[STATIC AVOID SPEED] 25.0 km/h
```

First test without transmission:

```bash
python3 src/main_integrated_v1.py --traffic --static --max-speed 57
```

Only after test pass, supervised MORAI low-risk scenario drive:

```bash
python3 src/main_integrated_v1.py --drive --traffic --static --static-control --max-speed 57
```

In `WP590-760`, logs should show `STATIC: AVOIDING` and
`FINAL TARGET` at most 25 km/h (possibly lower due to V7 or traffic).
Outside that zone without a latched avoidance path, static should be
`ZONE_OFF`.

Only `src/main_integrated_v1.py` transmits `EgoCtrlCmd`.
Never run the legacy LiDAR driving sender in parallel.
